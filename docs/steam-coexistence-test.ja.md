# Steamを起動したまま使う試験

この機能は実機での動作確認中です。SteamとRemapconが同じ物理コントローラーを共有すると、Steam側の割り当てが重複して送信される可能性があります。RemapconはSteamの設定を自動変更しません。

## 準備

試験版ZIPはGitHub Actionsの実行画面にある「Remapcon-Windows-x64」から取得できます。公開版を残すため、別フォルダに展開してください。設定は同じ端末のRemapconと共有されるため、先に設定画面からエクスポートしておくと戻しやすくなります。

1. Steamの「設定」→「コントローラ」→「デスクトップレイアウト」で、空のレイアウトを選びます。画面に「Steam Inputを無効化」がある場合は、それを選んでもかまいません。元に戻せるよう、変更前のレイアウト名を控えてください。これはSteamゲームごとのレイアウトとは別の設定です。
2. Steamボタンとの組み合わせでオンスクリーンキーボードが開く場合は、Steamのガイドボタンの組み合わせ設定も確認してください。デスクトップレイアウトを空にするだけでは、組み合わせ設定まで無効になるとは限りません。
3. Steamを起動し、コントローラーを接続します。まず対象アプリ以外のデスクトップで、ボタンやパッドが勝手にキー・マウス入力を送らないことを確認します。
4. Remapconで対象アプリを指定し、「前面で自動有効」をオンにします。Remapconの「設定」→「Steamとの併用（試験的）」をオンにします。手動での「有効にする」には共有アクセスを使いません。

対象アプリをSteamライブラリから起動している場合、Steamがそのゲーム用のレイアウトを適用する可能性があります。この手順は、対象アプリをSteam以外から起動する場合の確認を優先します。

## 確認すること

1. Steamを起動したまま対象アプリを前面にします。Remapconの状態が「自動有効」または「共有中」になり、設定したキー・マウス操作が1回だけ入力されることを確認します。「共有中」は排他アクセスを取れず、共有アクセスで動作していることを示します。状態が「取得不可」の場合は共有読み取りもできていません。
2. 対象アプリ内で、Steamのデスクトップ用キー、マウス操作、オンスクリーンキーボードが重複して出ないことを確認します。特に十字キー、左スティック、A、Steamボタンの組み合わせを試してください。重複したら成功とは扱わず、Remapconの試験的な設定をオフにしてください。
3. ボタンを押したまま対象アプリから離れ、キーが解除されることを確認します。Remapconの状態は「自動待機中」に戻ります。
4. Steamからゲームを起動し、コントローラーがそのゲームのSteam Inputで通常どおり動くことを確認します。対象アプリへ戻る場合も、手順1と2を再確認します。
5. Steamゲームを終了し、対象アプリに戻って再度動作を確認します。無線PuckとUSBの両方を使う場合は接続方式ごとに確認してください。

共有アクセスの取得はWindowsのHIDハンドルの共有条件と、先にコントローラーを開いているプロセスの設定に依存します。Steamが起動していても、必ず共有できるとは限りません。また、Steam側のレイアウトやガイドボタンの設定はRemapconから検査できません。
